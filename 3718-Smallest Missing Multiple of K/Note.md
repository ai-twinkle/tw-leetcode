# 3718. Smallest Missing Multiple of K

Given an integer array nums and an integer `k`, 
return the smallest positive multiple of `k` that is missing from `nums`.

A multiple of `k` is any positive integer divisible by `k`.

**Constraints:**

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`
- `1 <= k <= 100`

## 基礎思路

本題要求找出「最小的、且未出現在給定陣列中的正倍數」。表面上這是一個搜尋問題，但約束條件給出了極強的限制：陣列元素與長度皆不超過 100，因此整個問題的搜尋空間是有界且極小的。

在思考解法時，可掌握以下核心觀察：

- **數值範圍固定且狹窄**：
  所有可能出現的元素都落在 1 到 100 之間，因此可用一張固定大小的存在性表格直接標記，查詢成本降為常數。

- **倍數具有天然的遞增順序**：
  由小到大依序枚舉倍數，第一個未被標記的即為答案，無須排序或額外比較。

- **超出範圍的倍數必然缺席**：
  由於陣列中不可能出現大於 100 的值，任何超過此上界的倍數必定不存在於陣列中，因此搜尋只需在有界區間內進行。

- **邊界情形可直接由公式推得**：
  若區間內所有倍數都已出現，則答案必為第一個超出上界的倍數，可用整數除法直接算出，不必繼續迭代。

依據以上特性，可以採用以下策略：

- **先以固定大小的存在性表格標記所有出現過的數值**，將後續查詢轉為常數時間。
- **由最小的倍數開始遞增枚舉，遇到第一個未被標記者立即回傳**。
- **若有界區間內全數命中，則以公式直接算出第一個超界的倍數作為答案**。

此策略充分利用題目給定的窄值域，將問題化簡為一次線性標記加上一次有界掃描。

## 解題步驟

### Step 1：建立存在性標記表並取得輸入長度

由於可能出現的值僅限 1 到 100，配置一張固定 101 格的表格即可涵蓋所有情況；同時取出陣列長度以供後續掃描使用。

```typescript
// 只有 1..100 的值可能出現，因此固定 101 格的表格已足夠。
const presence = new Uint8Array(101);
const length = nums.length;
```

### Step 2：標記所有出現過的數值

逐一走訪輸入陣列，將每個出現過的數值在表格中對應位置標記為已存在，使後續查詢可在常數時間內完成。

```typescript
for (let index = 0; index < length; index++) {
  presence[nums[index]] = 1;
}
```

### Step 3：由小到大掃描範圍內的倍數

從最小的倍數開始遞增枚舉，直到超過值域上界為止；一旦發現某個倍數未被標記，即為所求的最小缺席倍數，可立即回傳。

```typescript
// 任何大於 100 的倍數皆超出值域範圍，因此必定缺席。
for (let multiple = k; multiple <= 100; multiple += k) {
  if (presence[multiple] === 0) {
    return multiple;
  }
}
```

### Step 4：處理範圍內倍數全部命中的情況

若掃描結束仍未找到缺席者，代表值域內的倍數皆已出現，此時答案必為第一個超出上界的倍數，可用整數除法直接推得。

```typescript
// 範圍內的倍數全部存在，因此回傳第一個超出範圍的倍數。
return (Math.floor(100 / k) + 1) * k;
```

## 時間複雜度

- 標記存在性需走訪整個輸入陣列一次，為 $O(n)$；
- 掃描倍數最多進行 $100 / k$ 次，在給定約束下為常數時間；
- 最終的公式計算為常數時間。
- 總時間複雜度為 $O(n)$。

> $O(n)$

## 空間複雜度

- 僅使用一張固定 101 格的標記表，大小不隨輸入增長；
- 其餘皆為固定數量的純量變數。
- 總空間複雜度為 $O(1)$。

> $O(1)$
